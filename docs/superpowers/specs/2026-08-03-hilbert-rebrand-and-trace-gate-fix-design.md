# Fix issue #40 (trace-session gate) + adapt the repo to the Hilbert rebrand

Date: 2026-08-03
Status: design approved, pending spec review

## Problem

Two coupled problems, discovered while investigating GitHub issue #40.

### 1. The trace-session gate blocks every fresh clone (issue #40)

The committed hook `.yukon/hooks/yukon-trace.sh` (commit `5dede4d`, 2026-07-09)
predates the CLI's `trace session` subcommand and the `TRACE_CONFIG_VERSION`
scheme. It unconditionally forwards to `yukon trace hook` and never calls
`trace session`, so the session marker the gate reads
(`~/.local/share/<cli>/trace/sessions/session-<id>.json`) is never written.

On a CLI new enough to enforce the gate (v2026.07.25-3+), that makes **every
command except `clone` permanently fail** in a fresh clone, and the error's
remediation ("restart the agent") cannot work because the hook physically
cannot register a session. The committed hook also carries no
`# <cli>-trace-config-vN` marker, confirming it predates the versioning scheme.

Verified locally in this repo: the committed script does
`agent="${1}"; event="${2}"; shift; shift` then always calls
`... trace hook "$agent" "$@"` (with `"$@"` empty); `grep -c` for the config
marker returns 0; `~/.local/share/*/trace/sessions/` did not exist.

**The fix is entirely repo-side. No Hilbert/Yukon CLI change is required to
unblock clones.** The CLI's own `trace init` regenerates the current v15 hook,
which contains the missing `session` branch.

### 2. The CLI has rebranded `yukon` -> `hilbert`

The current CLI (v2026.08.02-2, `TRACE_CONFIG_VERSION = 15`) is named `hilbert`.
The repo still carries the old `yukon` trace infrastructure and ~24 prose
references to "Yukon" as the grading platform. Running `hilbert trace init`
(the fix for problem 1) also regenerates the trace infra under the new brand,
so the two problems are naturally fixed together.

## Findings that shaped the design

- **The grading workflow is self-contained.** `.github/workflows/benchmark.yml`
  never invokes `yukon`/`hilbert`; the platform *dispatches* it. Its "Yukon"
  mentions are comments only. The functional platform dependency is the trace
  gate (fixed here) and the `benchmark.json` manifest schema.
- **The repo does not document the CLI to contestants.** README "How to play"
  points at `RULES.md` (the local build/run/commit loop) plus a Git-LFS note;
  `clone`/`submit` happen via the website + CLI, which the maintainer manages.
  There is therefore no in-repo home for CLI-version guidance.
- **`benchmark.json` carries no brand strings.** schemaVersion 1 fields
  (`editablePaths`, `setupCommand`, `benchmarkCommand`, `scorePath`, `runner`).
  It matches what the current CLI expects; expected to need no change, verified
  not assumed.
- **`.claude/settings.local.json` is gitignored** (per-machine; regenerated by
  `clone`). It is where Claude's SessionStart->session-registration wiring
  lives, but it is not committed, so it is not part of the repo change.
- **Local `yukon` binary is legacy.** This machine's `~/.local/bin/yukon` is a
  pre-rebrand wrapper; it still answers to the CLI. A fresh contestant install
  provides `hilbert`. The regenerated hooks correctly call `hilbert` (the
  current binary name); the repo tracks the CLI's current output, not this
  machine's legacy install.

## Scope

### Layer 1 - Trace infrastructure (this is the issue #40 fix)

Adopt the CLI-generated output of `hilbert trace init` (already present in the
working tree):

- Remove `.yukon/hooks/yukon-trace.sh` and `.opencode/plugin/yukon-trace.ts`.
- Add `.hilbert/hooks/hilbert-trace.sh` (v15, contains the `session` branch),
  `.omp/extensions/hilbert-trace.ts`, `.pi/extensions/hilbert-trace.ts`,
  `.opencode/plugin/hilbert-trace.ts`.
- Update `.codex/config.toml`, `.cursor/hooks.json`, `opencode.json` to point at
  the new hook.
- `.claude/settings.local.json`: no repo change (gitignored; regenerated by
  `clone`).

### Layer 2 - Prose / brand rebrand (live files only)

Replace "Yukon" with "Hilbert" in files that describe the live system:

- `src/main.rs`, `src/corpus.rs`, `src/purity.rs` (code comments; no logic).
- `.github/workflows/benchmark.yml` (comments describing the platform).
- `docs/END-TO-END.md`, `docs/WORKFLOW.md`, `docs/HARNESS-DESIGN.md`.
- Fix the dangling `docs/PUBLISH-TO-YUKON-PLAN.md` reference in
  `benchmark.yml` (rename the brand in the mention; the doc does not exist, so
  no file is created and no live link is introduced).

**Excluded (maintainer decision): dated historical records** under
`docs/superpowers/specs/` and `docs/superpowers/plans/` keep their original
"Yukon" wording — they record what was true when written.

Note on "frozen" files: the CLAUDE.md/HARNESS-DESIGN "frozen" markers are a rule
for competition *contestants*, not for maintainers building the competition.
Editing `benchmark.yml`/`benchmark.json`/docs for the rebrand is in bounds.

### Layer 3 - Manifest sanity check

Confirm `benchmark.json` still matches the current CLI's expected manifest
schema. Expected: no change. Verify against the CLI rather than assume.

## Out of scope (Hilbert-CLI-side; recorded, not implemented)

Issue #40 suggestions 2-4 are platform hardening, not needed for a contestant on
a current CLI to participate smoothly (a correct clone's SessionStart hook
registers the session on its own once Layer 1 lands):

2. Version-guard the gate error message (detect a pre-v15/marker-less script and
   advise `hilbert trace init` instead of "restart").
3. Stop swallowing hook stderr; leave a failure breadcrumb.
4. Self-healing gate: register the session on the spot when the marker is absent
   but the environment identifies a supported agent.

Residual risk these would cover: **CLI/hook version skew** (a contestant running
a CLI whose template differs from the committed hook). Mitigation that is in our
control: the maintainer's **website instructions** should tell contestants to be
on a current `hilbert` CLI (`hilbert update`). The CLI bundles and versions the
skill with itself ("do not mix versions"), so a current install is matched to
the committed v15 hook. This guidance lives on the website, not in the repo,
because the repo does not otherwise document the CLI.

## Acceptance criteria (end-to-end)

1. `cargo test` passes (Invariant 5). Layer 2 edits are comment/prose only, so
   no behavior change is expected; confirmed, not assumed.
2. Trace gate: invoking the regenerated hook as `hilbert-trace.sh <agent>
   session` registers the marker and `hilbert trace status` reports a registered
   session. (Already verified for the regenerated hook during investigation.)
3. CLI loop: `hilbert setup` succeeds and `hilbert run` produces a valid
   `score.json` (full `cargo build --release` + scored run).
4. `git grep -il yukon` returns only the excluded historical docs under
   `docs/superpowers/`.

## Cannot be verified locally (maintainer's steps, stated so nothing false is claimed)

- The platform dispatching `benchmark.yml` on GitHub Actions.
- The benchmark reimport into Hilbert.
- The website instruction update (including the CLI-version-currency note).

## Risks

- **Version skew (residual):** covered above; mitigated by website guidance,
  fully closed only by CLI-side #2-#4.
- **Comment-only edits touching frozen files:** acceptable per the maintainer
  clarification; no workflow logic or manifest semantics change.
