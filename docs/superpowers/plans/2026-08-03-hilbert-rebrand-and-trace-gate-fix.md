# Hilbert Rebrand + Trace-Gate Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix issue #40 (the trace-session gate that blocks every fresh clone) by adopting the current Hilbert-CLI trace hooks, and rebrand the repo's live "Yukon" references to "Hilbert".

**Architecture:** Two layers on one branch (`fix/issue-40-hilbert-rebrand`). Layer 1 replaces the stale `.yukon/` trace infrastructure with the CLI-generated `.hilbert/` output (the v15 hook has the `session` branch that registers the gate marker — this *is* the #40 fix). Layer 2 is a mechanical `Yukon`→`Hilbert` prose rebrand in live code comments and docs. The grading workflow is self-contained and dispatched by the platform, so no logic changes — only comments and trace wiring.

**Tech Stack:** Rust (harness), shell (trace hooks), GitHub Actions (grading), Hilbert CLI (`hilbert`, currently v2026.08.02-2, `TRACE_CONFIG_VERSION = 15`).

## Global Constraints

- Branch: all work on `fix/issue-40-hilbert-rebrand`; `main` stays at `origin/main`. (Verbatim from maintainer: fix must be PR-able off a separate branch.)
- No Hilbert/Yukon CLI changes — repo-side only. (Spec: issue #40 is fixable repo-side.)
- Contract frozen for *contestants*, not maintainers: editing `benchmark.yml`/`benchmark.json`/docs for the rebrand is in bounds. (Maintainer clarification.)
- `cargo test` passes at the end (CLAUDE.md Invariant 5).
- Exclude dated historical docs under `docs/superpowers/specs/` and `docs/superpowers/plans/` from the rebrand — leave their "Yukon" wording. (Maintainer decision; note THIS plan file and the spec file are themselves under that path and must NOT be rebranded.)
- Trace infra content is authoritative CLI output (`hilbert trace init`); do not hand-edit generated hooks.
- The regenerated working-tree changes from `hilbert trace init` are already present (staged as unstaged modifications) — Task 1 commits them, it does not regenerate them. If they are somehow missing, regenerate with `hilbert trace init` before committing.
